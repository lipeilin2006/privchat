# 安全与信任模型

本文记录 PrivChat 的威胁模型、信任边界、已知问题与密码学参数。
基于 `main` 分支（SimpleX 式单向队列协议）。

---

## 1. 信任边界

| 角色 | 谁负责它的可信度 | 客户端对它的假设 |
|---|---|---|
| **mailbox 节点**（存储转发） | **用户自己**：用哪台、是否自建，由用户决定 | 只提供传输与存储；**内容安全完全不依赖它** |
| mailbox 之间的同步网络 | **mailbox 运营者**：邻居表、同步认证、限流归节点自己 | 客户端不关心，同步内容仍只是密文 |
| 洋葱中继（可选） | 用户配置 | 只做逐层转发，看不到明文 |
| 对端设备 | 对端自己 | 只信任「拿到邀请的人」 |
| 本机 | 用户自己 | SQLCipher + 密码 |

结论：**mailbox 可以是恶意的**。它能破坏可用性、能看元数据，
但看不到也用不了消息内容——内容安全由端到端密钥保证，不依赖节点诚实。

## 2. 协议概要

```
邀请   = (mailbox, queue_id, owner_ek, sender_sk)   // 线下交换（二维码/链接）
建立   = 双方各自建一条接收队列；互扫后 root = HKDF(DH(ek_a, ek_b))
消息   = ChaCha20-Poly1305(AAD = header(n, ek, nonce))
队列   = Ed25519 签名 (domain || queue_id || 密文)，节点验签后存储
读取   = owner 签名 (domain || queue_id)，节点取回即删
```

- 每条连接独立密钥，**没有全局身份**：换设备/重装 = 重新加好友。
- 方向链按公钥字典序区分，双方不会用同一条链。
- 链密钥每条消息推进一次（对称棘轮），乱序窗口 200。

## 3. 恶意 mailbox 能做什么

| 能力 | 影响 | 客户端是否可检测 |
|---|---|---|
| 读取/丢弃/延迟消息 | 可用性 | 不能（但不会丢密钥） |
| 留存密文（harvest now, decrypt later） | 与设备失窃叠加时才有意义 | 不能 |
| 重放旧消息 | 无（序号 + 已用密钥拒绝） | 能，直接丢弃 |
| 存垃圾 / 绕过验签 | 无（收端解不开） | 能（解密失败） |
| 统计时间、大小、队列对 | 元数据泄漏 | 不能 |
| 删除队列 | 可用性 | 不能 |

**它不能**：解密、伪造可解密的消息、把 A 的消息冒充成 B 的。
签名只绑定「写权限」，真正的身份由邀请携带的连接公钥决定。

## 4. 已知问题（按严重度）

| # | 问题 | 说明 |
|---|---|---|
| S1 | **没有前向保密对抗设备失窃** | 连接状态里保留了 `root`，拿到数据库的人可以重算初始链密钥并往前走，历史消息全解。应改为派生完链就丢弃 root。 |
| S2 | 无后妥协恢复 | 只有对称棘轮；需要定期 `rotate()` 换连接密钥。 |
| S3 | 元数据 | 队列 id、时间、长度、同一 mailbox 下的队列对都可关联；未做队列轮换与填充。 |
| S4 | 可用性 | 没有多路冗余/重试策略；节点丢消息就是丢。 |
| S5 | 队列写权限即邀请 | 邀请泄露 = 可以往队列灌垃圾（但解不开）。现阶段没有轮换写 key 的 op。 |
| S6 | 节点侧无速率限制 | 单队列可被灌满（16MB/条，TTL 默认 7 天）。 |
| S7 | 洋葱为可选 | 开启时首跳仍能看到上传者的 TLS 身份（每条连接独立身份，已缓解）。 |

## 5. 密码学参数

| 项 | 取值 |
|---|---|
| 连接密钥交换 | X25519，`root = HKDF(SHA-256, DH)` |
| 链推进 | HKDF-SHA256，每条消息一次 |
| 消息加密 | ChaCha20-Poly1305，头部作 AAD |
| 队列签名 | Ed25519，覆盖 `domain || queue_id || payload` |
| 乱序窗口 | 200 条 |
| 本地库 | SQLCipher（全库加密） |
| 邀请编码 | base64url，约 150 字符 |

## 6. 形式化验证

`/root/privchat-proverif/privchat_conn.pv`（ProVerif 2.05）验证：

- 载荷保密：恶意 mailbox + 邀请泄露（拿到写权限）仍解不开；
- 认证：接收方接受的消息必由发送方发出；
- 前向保密（链密钥层面）：拿到推进后的链密钥解不开旧消息。

**未覆盖**：`root` 保留导致的「设备失窃可解历史」（S1），模型里没有建模 root。
反证对照 `privchat_conn_neg.pv` 说明模型非空。

---

## 7. 部署建议

- mailbox 自建或选可信运营者（信任边界在用户）。
- 多台 mailbox 冗余，避免单点可用性问题。
- 生产环境开启洋葱时，中继与终点分离运营。
- TTL 按需调短，减少元数据留存。
